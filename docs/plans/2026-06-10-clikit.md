## 0. Product summary

`clikit` does for command-line tools what chassis already did for services: turns every CLI
in the fleet from a hand-built snowflake into a consistent, production-grade tool that can be
stood up in an afternoon and scripted against blindly.

chassis standardized **services** (config, logging, health, shutdown, observability) but stopped
halfway for **CLIs and batch tools** — giving them config + a logger, then abandoning them at the
part that makes a CLI a CLI: subcommands, flags, help text, output formatting, exit codes. Today
each tool reinvents that layer inconsistently (`-o` vs `--out` vs `--output-file`; JSON vs text vs
stack-trace errors; some have `--version`, some don't; some leak ANSI into log files). CLIs are the
fleet's snowflakes — the exact thing chassis exists to eliminate.

`clikit` closes that gap: one way to declare a command, one options struct that drives **both** env
vars and flags, one conventional flag set every tool gets, and a strict results-to-stdout /
diagnostics-to-stderr discipline that makes every CLI pipeable and automatable.

## 1. Non-negotiable principles (every decision honors these)

1. **Toolkit, not framework.** clikit never owns `main()` or calls `os.Exit`. The dev writes
   `main`, calls `chassis.SetAppVersion`/`RequireMajor`, constructs an `App`, registers `Command`
   values whose handlers they wrote, and calls `os.Exit(app.Run(os.Args))`. No reflective discovery
   of the dev's package; control never inverts.
2. **Tier-1 purity is a published contract.** `README` guarantees *"If you only use Tier 1 packages,
   only `golang.org/x/sync` is pulled in."* clikit adds **zero** new `go.mod` requires. TTY detection
   is stdlib (`os.ModeCharDevice`).
3. **Fail-fast, but never via `os.Exit`/panic from inside clikit.** Bad command/flag/required-value →
   actionable stderr + non-zero return code, *before* any handler runs. All `flag.FlagSet`s use
   `ContinueOnError` (stdlib default `ExitOnError` would call `os.Exit`, breaking the boundary).
4. **stdout is the product; stderr is the diagnostics.** Results → stdout via an explicit `Emitter`
   (`ctx.Out`); logs/progress/errors/usage → stderr (extends `logz`'s stderr-only contract). This is
   what makes `--json` pipeable and is the load-bearing decision.
5. **Compose, don't reinvent.** clikit is glue over `chassis`, `config`, `logz`, and opt-in
   `registry`. New code is confined to: subcommand router, env+flag binder, and the
   stdout/stderr+color/`--json` output layer.

## 2. Settled decisions (ADR digest — full ADR in §10)

| # | Decision | Choice | Why |
|---|---|---|---|
| D1 | Placement | In-module `.../v11/clikit` (not `chassis-go-addons`) | Foundation, not addon; Go isolates deps at the *package* level so a separate module buys zero isolation for a stdlib-only kit; avoids version-skew vs `RequireMajor`. |
| D2 | TTY detection | stdlib `os.Stat(os.Stdout).Mode()&os.ModeCharDevice` (not `x/term`) | Adding `x/term` as a direct require breaks the published Tier-1 "only `x/sync`" guarantee. Char-device check is sufficient for *color gating*. |
| D3 | env+flag binder | sibling binder in clikit; reuse config's tag vocabulary + new error-returning `config.Convert`/`config.Check` | `config.validateField` panics; keeps `config` a pure env loader exposing value-conversion only. |
| D4 | Precedence | `flag.FlagSet.Visit`-based resolution (not default-seeding) | Exact `flag > env > default` for all 7 types incl. bool-explicit-false and `[]string`-replace. |
| D5 | Command model | struct with `Run func(ctx, *Context) error` field, flat name→Command map | Low boilerplate for many tiny CLIs; mirrors `lifecycle.Component` / `registry.Handle`. |
| D6 | Boundary | `App.Run(args) int`, dev owns `os.Exit`; `ContinueOnError` + per-handler `recover()` | clikit never exits/panics across the seam. |
| D7 | Output | stdout=results via `Emitter`; stderr=logs; `--json`=one bare JSON value (no v1 envelope) | Pipeable; Interpretation B (raw `fmt.Println` is the dev's bug, negative-tested). |
| D8 | Signals | clikit-owned `signal.NotifyContext`, **not** `lifecycle.Run` | CLIs aren't services — no heartbeat/poll/errgroup machinery. |

## 4. Public API surface

```go
package clikit

// ---- Bootstrap / composition root ----

type Config struct {
    Name        string     // display name; default filepath.Base(os.Args[0])
    AppVersion  string     // informational; the DEV calls chassis.SetAppVersion in main()
    UseRegistry bool       // opt-in registry.InitCLI (stop/visibility). Default false.
    StdFlags    StdFlagSet // which conventional flags to inject (§7)
}

// App is the composition root. It owns NOTHING of main()'s control flow.
type App struct { /* unexported */ }

// New builds the App. It does NOT run the chassis prologue — the DEV calls
// chassis.SetAppVersion + chassis.RequireMajor in main() BEFORE app.Run.
func New(cfg Config) *App

// Command registers a subcommand. Chainable. On programmer error (empty/dup
// Name, nil Run) Run reports ExitUsage with a clear message — it does NOT panic.
func (a *App) Command(c Command) *App

// Run parses args[1:], selects+executes a command, returns a PROCESS EXIT CODE.
// The dev writes: os.Exit(app.Run(os.Args)). clikit itself never calls os.Exit.
func (a *App) Run(args []string) int

// SuppressAutoRebuild sets CHASSIS_NO_REBUILD=1. MUST be called in main() BEFORE
// chassis.RequireMajor() to take effect (freshness is decided inside RequireMajor,
// which runs before any App exists). For cron/CI/distroless CLIs. See §6.
func SuppressAutoRebuild()

// ---- Commands ----

type Command struct {
    Name  string
    Short string
    Long  string
    Flags any // *struct with flag/env/default/required/validate/usage tags; bound before Run
    Run   func(ctx context.Context, cctx *Context) error
}

type Context struct {
    Args    []string     // positionals after the command's flags; includes everything after "--"
    Options any          // same pointer as Command.Flags, now populated (flag>env>default)
    Log     *slog.Logger // -> STDERR (logz JSON, or clikit pretty text on interactive TTY)
    Out     *Emitter     // -> STDOUT (text, or one JSON value under --json)
    Color   ColorMode
}

// ---- Exit codes ----

const (
    ExitOK    = 0 // success
    ExitError = 1 // generic handler error
    ExitUsage = 2 // usage / unknown command / bad flag / missing required / dup flag / nil Run
)

// ExitErr lets a handler request a specific code: return clikit.ExitErr{Code: 3, Err: ...}.
type ExitErr struct { Code int; Err error }
func (e ExitErr) Error() string

// ---- Env+flag binding ----

func Bind(fs *flag.FlagSet, structPtr any) (*Binding, error) // dup pre-check; errors before registering
func (b *Binding) Resolve(fs *flag.FlagSet) error            // Visit-based flag>env>default; required+Check; never panics

// ---- Output ----

type Emitter struct { /* w=os.Stdout; json bool; color ColorMode */ }
func (e *Emitter) Printf(format string, a ...any) // human stdout; NO-OP under --json
func (e *Emitter) Println(a ...any)               // human stdout; NO-OP under --json
func (e *Emitter) Emit(v any) error               // --json: one bare JSON value; else pretty text
func (e *Emitter) JSON() bool

// ---- Color ----

type ColorMode int
const ( ColorAuto ColorMode = iota; ColorAlways; ColorNever )
func (m ColorMode) Enabled(out *os.File) bool // applies the §8 truth table for this stream
func (m ColorMode) Bold(s string) string      // SGR helpers; identity when disabled
func (m ColorMode) Red(s string) string
func (m ColorMode) Dim(s string) string
```

### Canonical "after" CLI (`examples/05-clikit/main.go`) — the <=15-line target

```go
package main

import (
	"context"
	"os"

	chassis "github.com/ai8future/chassis-go/v11"
	"github.com/ai8future/chassis-go/v11/clikit"
)

type greetOpts struct {
	Name string `flag:"name" env:"GREET_NAME" default:"world" validate:"min=1" usage:"who to greet"`
	Loud bool   `flag:"loud" env:"GREET_LOUD" default:"false" usage:"shout it"`
}

func main() {
	chassis.SetAppVersion(chassis.Version) // mandated; enables --version + freshness
	chassis.RequireMajor(11)               // runs BEFORE app.Run (ordering contract, §6)

	app := clikit.New(clikit.Config{Name: "demo", StdFlags: clikit.DefaultStdFlags()})

	opts := &greetOpts{}
	app.Command(clikit.Command{
		Name: "greet", Short: "Print a greeting", Flags: opts,
		Run: func(ctx context.Context, c *clikit.Context) error {
			c.Log.Debug("greeting", "name", opts.Name) // -> stderr
			return c.Out.Emit(map[string]any{"greeting": "hello, " + opts.Name, "loud": opts.Loud}) // -> stdout
		},
	})

	os.Exit(app.Run(os.Args)) // dev owns os.Exit; clikit returns the code
}
```

## 5. Unified env+flag tag design

- **Tags:** `flag:"name"` (new; len-1 ⇒ `-x`, longer ⇒ `--name`; omit ⇒ env-only field still loaded),
  plus `env`/`default`/`required`/`validate` (identical to config), and `usage:"text"` (new, for help).
- **Precedence via `flag.FlagSet.Visit`:** register each flag with the `default:` tag as its stdlib
  default; `fs.Parse(args)`; collect explicitly-set names with `fs.Visit`; then per field resolve
  **set→flag, else env-present→env, else→default**. Exact for all 7 types including bool explicit
  `--loud=false` (Visit sees it; seeding could not distinguish it from the zero value) and `[]string`
  multi-element (`--tag a --tag b` accumulates; resolution replaces env rather than appending).
- **Duplicate flag names:** `Bind` pre-checks and returns a clean error **before** any `fs.Var` call
  (stdlib `flag.FlagSet` panics on duplicate registration → boundary break).
- **`required` + `validate`:** after `Resolve`, a still-zero required field → `ExitUsage` with
  `clikit: required flag --x (env VAR) not provided` + command usage to stderr. Validation runs
  through `config.Check` (error-returning).

### config refactor (additive, non-breaking)

```go
// Convert parses raw into proto's dynamic type and returns the value. Never panics.
func Convert(proto any, raw string) (any, error)
// Check validates v against a validate tag and returns an error. Never panics.
func Check(name string, v any, validateTag string) error
```

Internals refactor so `MustLoad`'s panic sites call these error-returning cores.

> **Parity guard (Critic ratification item):** `MustLoad` must preserve the existing
> required-missing **string** panic (`panic(fmt.Sprintf("config: required environment variable %q ...", ...))`)
> — or wrap converter errors with `panic(err.Error())` (string) — so that
> `TestMustLoad_PanicsOnMissingRequired` (`config_test.go:118`, asserts `recover().(string)` contains
> the var name) stays green. The other 8 panic tests only assert `recover() != nil` and are
> parity-safe. `MustLoad`'s public behavior (panic-on-bad-config at startup) is unchanged; parity tests
> prove it. config's identity ("populates structs from environment variables") is preserved — it
> exposes conversion, never `os.Args` or flag shape.

## 6. Auto-rebuild / freshness interaction

- **clikit does NOT disable freshness.** `chassis.RequireMajor` → `checkFreshness` (`chassis.go:47`)
  may rebuild + re-exec a stale binary when `SetAppVersion` is set — mandated repo policy.
- **Ordering contract (documented + shown in the example):** the dev calls `chassis.SetAppVersion` +
  `chassis.RequireMajor` in `main()` **before** `app.Run`. clikit does its work *around* this.
- **Opt-out — honest mechanism (Critic ratification item):** the **only** working off-switch is the
  `CHASSIS_NO_REBUILD` env var, read inside `checkFreshness` (`freshness.go:147`) which runs **before**
  any clikit `App` exists. Therefore there is **no `Config.NoAutoRebuild` field** (it would be dead
  code — a struct field cannot suppress a rebuild that already executed). Instead clikit ships
  `clikit.SuppressAutoRebuild()`, documented "call in `main()` BEFORE `chassis.RequireMajor()`", which
  sets the env var. For cron/CI/distroless CLIs that need fast cold-start or lack a Go toolchain.
- **Integration test:** `subprocess_test.go` covers toolchain-present (stale binary rebuilds) and the
  suppressed path (no rebuild attempt).

## 7. Default & suggested flag set

| Flag | Category | Effect |
|---|---|---|
| `--version` | Automatic (chassis) | Handled in `chassis.RequireMajor`→`checkVersionFlag` **before** `app.Run`. clikit MUST NOT register it (double-register → panic; a test asserts no double-register). |
| `--help` / `-h` | Automatic (clikit) | clikit FROZEN renderer; intercepted before `Parse`. Requested ⇒ **stdout, exit 0**. Error usage ⇒ **stderr, exit 2**. |
| `--json` | Suggested (in `DefaultStdFlags`) | Emitter→one bare JSON value; logz→JSON stderr. |
| `--log-level` | Suggested | Sets stderr logger level. |
| `-v`/`--verbose` | Suggested | ⇒ debug. |
| `-q`/`--quiet` | Suggested | ⇒ error. |
| `--color`/`--no-color` | Suggested | ⇒ `ColorAlways`/`ColorNever`. |

**Rules:** `--version`/`--help` always present. Others opt-in via `StdFlagSet` but on under
`DefaultStdFlags()`; `clikit.StdFlagSet{}` ⇒ only version/help. **Global flags MUST precede the
subcommand** (stdlib `flag` stops at the first non-flag token — documented). `-v`/`-q`/`-h` are
**reserved globally**; commands may not reuse them (Bind errors on collision). Explicit `--log-level`
wins over `-v`/`-q`. (Verified collision-free: `chassis.go:85` matches only the exact `--version`
token; registry has no `-v/-q/-h`.)

## 8. stdout/stderr + color + `--json` model

| Channel | Carries | Writer | Mode behavior |
|---|---|---|---|
| **stderr** | logs, progress, errors, usage-on-error | `logz` logger or clikit pretty handler | `--json` ⇒ `logz.New` (JSON). Interactive TTY, no `--json` ⇒ clikit **pretty text** slog handler. Non-TTY, no `--json` ⇒ `logz.New` (JSON, redirect-safe). |
| **stdout** | command **results** only, via `ctx.Out` | `os.Stdout` | `--json` ⇒ `Emit(v)` writes **exactly one bare JSON value** (handler owns shape; no v1 envelope); `Printf/Println` are **no-ops**. No `--json` ⇒ `Emit` pretty, `Printf/Println` human (colorized if enabled). |

- **stdout-suppression — Interpretation B:** only `Emitter`/`ctx.Out` writes are gated by `--json`.
  A raw `fmt.Println` in a handler is the **dev's bug**; `subprocess_test.go` includes a **negative
  test** proving a stray `fmt.Println` breaks `jq`, and `doc.go` states **"handlers MUST use ctx.Out."**
- **Pretty handler trace IDs:** the clikit text handler calls `trace.SpanContextFromContext(ctx)`
  directly (proven at `otel/otel.go:138`) to emit `trace_id`/`span_id` — **no new logz API**.
  `logz.New` is untouched for the JSON path. A test asserts `trace_id` survives in pretty/TTY mode.

### Color resolution truth table (per stream; stdout & stderr resolved independently)

Precedence, highest first:
1. `--color=always|never|auto` (explicit flag)
2. `NO_COLOR` set to any non-empty value ⇒ **disabled**
3. `FORCE_COLOR` set to any non-empty value ⇒ **enabled**
4. `ColorAuto` ⇒ `isTTY(stream)` via stdlib `os.Stat(stream).Mode()&os.ModeCharDevice != 0`

`isTTY` is a package func-var so tests inject fake TTY state without a real terminal.

### registry.InitCLI

clikit does **not** auto-register. `Config.UseRegistry` opt-in. When true, document the
`registry.parseFlags` (`registry.go:424`) limitation: **multi-subcommand flags are flattened and
subcommand identity is lost in the manifest.** Stated in `doc.go`; **not fixed in v1.**

### Signals

clikit owns its **own** `signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)`
(mirroring `lifecycle.go:107`), passed as the handler `ctx`. clikit **explicitly does NOT call
`lifecycle.Run`** — CLIs are not services. With `Config.UseRegistry:true`, the registry `stop` command
also cancels, but the base mechanism is the signal context.

### 9.3 Acceptance criteria (measurable)

1. **`--version`:** subprocess asserts exact stdout `demo X.Y.Z (chassis-go 11.a.b)\n` + exit 0; clikit
   registers no `--version` (no double-register panic).
2. **Precedence matrix:** for each of the 7 types — string/int/int64/float64/bool/`time.Duration`/`[]string` —
   rows `{flag>env}`, `{env>default}`, `{default-only}`, **plus** `bool` explicit `--loud=false`
   (⇒ false, beating env=true) and `[]string` multi (`--tag a --tag b` ⇒ `[a b]`, replacing env), each
   with exact expected values.
3. **`--json`:** subprocess pipes the built binary through real `jq -e .`; assert `json.Valid` on
   captured stdout, exactly one doc (no inter-doc newline), zero log lines on stdout, logs on stderr,
   jq exit 0.
4. **Color:** full truth table asserts ANSI present/absent; `isTTY` overridable.
5. **Fail-fast:** each bad-input condition (unknown command, unknown flag, missing required, dup flag,
   nil Run) maps to `ExitUsage`=2 with stderr usage.
6. **Signals:** SIGINT during handler ⇒ handler observes `ctx.Err()==context.Canceled`; documented exit code.
7. **Imports:** `go list -deps ./clikit` allowlist snapshot — no import outside
   {stdlib, chassis, config, logz, registry}; explicitly no `x/term`.
8. **`go vet ./clikit/...`** exit 0.
9. **"<=15-line main":** measured against `examples/05-clikit/main.go`, gofmt'd, non-blank/non-comment
   lines counted by the test (prologue + `os.Exit` included).

## 10. Architecture Decision Record

**Title:** ADR-001 — `clikit`: a stdlib-only, Tier-1 CLI toolkit for chassis-go
**Status:** Accepted (consensus iteration 2). **Date:** 2026-06-10.

**Decision.** Introduce `github.com/ai8future/chassis-go/v11/clikit`, a Tier-1, **stdlib-only** CLI
toolkit providing: (a) a non-`main()`-owning composition root (`App.Run(args) int`); (b) a
struct-with-func-field subcommand router; (c) a single options struct that drives **both** env and CLI
flags with exact `flag > env > default` precedence (via `flag.FlagSet.Visit`); (d) an explicit
stdout-results/stderr-diagnostics split via an `Emitter`, with `--json` writing one bare JSON value;
(e) optional colored stderr logs with TTY detection via stdlib `os.ModeCharDevice`. It composes
`chassis`, `config`, `logz`, and opt-in `registry`; it adds **no** `go.mod` dependency.

**Drivers.** (1) Preserve the published Tier-1 invariant (README: only `x/sync` pulled in). (2) Collapse
the repeated CLI prologue without inverting control (toolkit-not-framework). (3) One-struct-two-sources
with correct precedence for all 7 types incl. bool-explicit-false and `[]string`. (4) Process-level
correctness (exit codes, stdout/stderr separation, `--json` cleanliness, signal cancellation,
fail-fast) without clikit ever calling `os.Exit`/panicking across the boundary.

**Alternatives considered.**
- *Placement in `chassis-go-addons`* — rejected: Go isolates deps at the package level, so a separate
  module buys zero isolation for a stdlib-only kit; it would invert the dependency arrow and create
  version-skew against `RequireMajor`. (A future addons module is justified only for heavy third-party
  CLI sugar — Cobra-backed variants, bubbletea TUI — not for this stdlib core.)
- *TTY via `golang.org/x/term`* — rejected: new direct require breaks the Tier-1 `x/sync`-only
  guarantee; stdlib char-device check suffices for color gating.
- *Thin field-poking `config.SetValue/ValidateValue`* — rejected: `validateField` panics, forcing
  panics on clikit and breaking the no-panic boundary. Chose error-returning `Convert`/`Check`.
- *Extend `config` with flag awareness (`LoadWithFlags`)* — rejected: pollutes config's pure-env-loader
  identity and widens the most-imported package's surface for CLI-only benefit.
- *Precedence by default-seeding the FlagSet* — rejected: cannot distinguish `--bool=false` from the
  zero value and mishandles `[]string` append-vs-replace. Chose `fs.Visit`.
- *Command as an interface* — rejected: raises per-command boilerplate for many tiny CLIs;
  struct-with-func-field matches existing `lifecycle.Component`/`registry.Handle` and feeds auto-help.
- *clikit auto-runs the chassis prologue / disables freshness / calls `lifecycle.Run`* — rejected:
  would override mandated freshness policy, hide wiring, or impose service-grade machinery on CLIs.
- *`Config.NoAutoRebuild` field* — rejected during ratification: structurally non-functional because
  freshness is decided inside `RequireMajor` before any `App` exists. Replaced with the
  `SuppressAutoRebuild()` helper called before `RequireMajor`.

**Why chosen.** This is the minimal design that eliminates CLI boilerplate while honoring every chassis
invariant: tier purity (zero new deps), toolkit-not-framework (dev owns `main`/`os.Exit`, commands
passed in), fail-fast (no-`os.Exit`/no-panic boundary via `ContinueOnError` + dup pre-check + recover),
and operational visibility (opt-in registry, OTel trace IDs in both JSON and pretty logs).

**Consequences.**
- *Positive:* fleet CLIs shrink to a ~15-line `main`; consistent `--version/--help/--json/--log-level/--color`;
  clean pipeable stdout; Tier-1 dependency promise intact; config gains reusable, panic-free converters.
- *Negative / accepted:* TTY detection is a heuristic (color-only, mitigated by `NO_COLOR`/pipe);
  `config` gets a small additive refactor (parity-tested, with the string-panic guard); devs must keep
  the `SetAppVersion`→`RequireMajor`→`Run` ordering (documented + exemplified); the `registry` manifest
  can't distinguish subcommands under `UseRegistry` (documented, deferred).

**Follow-ups (explicitly out of v1 scope).** (1) `{schema_version, data}` `--json` envelope.
(2) Nested sub-subcommands via reserved `Command.Sub []Command`. (3) Shell-completion generation.
(4) Config-file source layered into precedence. (5) Fix `registry.parseFlags` to retain subcommand
identity. (6) Legacy-Windows VT/ANSI enablement. (7) Interactive prompts/TUI (bubbletea) — likely a
future `chassis-go-addons` module, not the core.

## 11. Risks & mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| `os.ModeCharDevice` heuristic imprecision vs `x/term` | Low | Only gates *color*; worst case = color to a non-TTY char device (harmless); `NO_COLOR`/pipe still suppress. Behind `isTTY` func-var seam ⇒ one-function swap if ever needed. |
| Toolkit→framework drift | High (identity) | `Run` returns `int`, dev calls `os.Exit`; commands passed in, never discovered; `ContinueOnError` everywhere; invariant stated in `doc.go`; reviewer gates future PRs that reach into app code. |
| `--json` leakage via raw `fmt.Println` | High (acceptance) | Interpretation B + **negative subprocess test** proving leakage breaks `jq`; `doc.go` mandates `ctx.Out`. |
| config refactor regresses an existing test | Med | Additive `Convert`/`Check`; **string-panic parity guard** for required-missing (`config_test.go:118`); `MustLoad` behavior unchanged; parity tests. |
| Auto-rebuild surprises (slow cold start / no toolchain) | Med | Documented ordering contract + `SuppressAutoRebuild()` (env-var, the only working switch) + toolchain-present/absent integration tests. Never overrides policy by default. |
| flag panics (dup registration; `ExitOnError` os.Exit) | Med | `ContinueOnError` + `Bind` dup pre-check + `defer recover()` per handler mapping to a documented code. |
| Global-vs-command flag ordering confusion | Med | Documented "globals precede subcommand"; reserved `-v/-q/-h`; segmentation tests. |
| registry manifest loses subcommand identity | Low | Documented under `UseRegistry`; not fixed in v1. |
| Naming confusion with `flagz` (feature flags) | Low | `doc.go` disambiguation. |
| Windows ANSI (future fleet) | Low (now) | Heuristic + ANSI are cross-platform enough for modern terminals; legacy-Windows VT deferred. |
